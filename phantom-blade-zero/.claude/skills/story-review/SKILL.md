对 `phantom-blade-zero` 库的**单篇**已有成稿做审校。**每次只跑一篇。**

## 参数

| 开关 | 默认 | 作用 |
|---|---|---|
| `--max N` | 3000 | 正文字符上限（含标点，不含换行） |
| `--scope 篇内\|篇间` | 篇内 | 篇内 = 不改名、不合并、不拆分；篇间 = 允许动结构 |
| `--wide` | 关 | 跨篇参照从「同桶 + 直接牵涉」放开到全库 |

权威原文目录写死为 `.source/`。

## 硬约束

1. 正文不超过 `--max` 字符（含标点，不含换行）。**用 python `len()` 数，不要用 `wc -m`**——Git Bash 下 locale 会按字节计，看起来像超限。
2. 全文只出现逗号、顿号、句号三类符号，其余只能是汉字与分段换行。没有引号、问号、感叹号、冒号、分号、破折号、省略号、括号、书名号，也没有阿拉伯数字与拉丁字母——年份一律写作「组织三十八年」这样的汉字。
3. 不写标题，正文第一句直接开始，段落之间空一行。
4. 严格依据 `.source/` 原文。原文无据的细节删去或模糊化：**宁可少写一句，不留一句没出处的**。
5. 默认篇内优化：不改文件名、不合并篇目、不拆分篇目。

## 六维度（按优先级）

1. **设定一致性** — 与 `.source/` 原文的人物关系、事件、时间不冲突
2. **跨篇一致性** — 同一事件在本篇与参照篇目里的表述不互相矛盾
3. **文学性** — 把「讲述」变成「呈现」：场景、细节、对话、留白、节奏
4. **人物弧光闭合** — 执念 → 崩塌 → 结局的因果链是否成立
5. **冗余** — 与他篇重复的内容
6. **体例统一** — 文体是否与同库其它篇目一致

## 跨篇参照范围

默认：**同桶全部篇目 + 该篇正文直接牵涉的相邻桶篇目**。`--wide` 放开到全库。

## 流程

1. 读成稿（主对话）。
2. 派 `story-reviewer` 子 agent（Agent 工具，`subagent_type: story-reviewer`），交给它：成稿路径、权威目录、需一并参照的篇目。它返回两段——**冲突／无据清单**、**事实摘要**。
3. 据清单 + 六维度，落改稿。
4. **直接写入原文件，不设确认环节。** 作者通过 `git diff` 复核，要回退自行 git 处理。
5. 输出**逐条改动说明**、**校验记录**、**待同步清单**。

## 冲突裁定权

- `.source/` 内部条目互相矛盾 → 按「**以更权威的条目为准**」先裁并标注理由，用户可推翻。势力总述与本人条目优先于边缘提及；2 比 1 以上时从多数。
- `.source/` 与现有正文冲突 → 一律以原文为准，列出差异后改。
- `.source/` 未提及、正文自行补写 → 不与原文冲突则保留（这是文学性增写）。

## 产出契约

- **改后全文** — 整篇贴出，不贴 diff。
- **逐条改动说明** — 逐条对应，「第 3 段：删去……因 `.source/XX.md` 无据」。
- **校验记录** — 本篇与 `.source/` 的每处差异、裁定理由、被删的无据细节。
- **待同步清单** — 本篇改动波及的其它篇目与段落，供用户跑下一篇时带回。

## 不落盘

除成稿本身外，分析、记录、清单都不写文件。

## 推荐顺序

一次一篇。`五指.md` 一类的总传压到分传定稿之后再跑——分传一改，总传就得跟着改。
